### Two real bugs found and fixed during the live browser walkthrough (not just unit-level — only surfaced by actually running the full stack):
1. **Scanner traffic was triggering SOC detections.** The scanner/verification HTTP calls (real exploit checks) tripped the same detection rules a live attacker would, creating incidents before anyone clicked "run attack" in Security Lab. Fixed by tagging all `CyberLabAdapter` traffic with a fixed `X-Forwarded-For: 10.50.0.1` (`SCANNER_SOURCE_IP` in `modules/cyberlab/adapter.ts`) and excluding that IP in `detection/service.ts` — the same way a real AppSec scanner's IP would be allowlisted out of SOC alerting. Verified: scan now produces 0 incidents; only the Security Lab "run attack" button produces the real one.
2. **SSE stream was CORS-blocked in the browser.** `/api/stream` writes the raw HTTP response directly (required for a streaming body), which bypasses Fastify's normal reply pipeline — so `@fastify/cors` never got to set `Access-Control-Allow-Origin` on it. Fixed by setting that header by hand in the raw `writeHead` call. Verified: SOC page now shows "● Live" and events stream in in real time when an attack runs in another tab.
